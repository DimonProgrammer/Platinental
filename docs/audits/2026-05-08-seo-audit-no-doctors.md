# SEO audit без страниц врачей

Дата: 2026-05-08  
Scope: текущая Astro-сборка, страницы `/`, `/about/`, `/contacts/`, `/documents/`, `/kosmecevtika/`, `/kosmetologiya/`, `/plastika/`, `/prices/`. Страницы `/doctors/*` и карточки врачей не оценивались по просьбе пользователя.

## Что проверено

- `npm run build` завершился успешно: 20 страниц сгенерировано.
- На страницах scope проверены `title`, `description`, canonical, Open Graph/Twitter, H1, JSON-LD, `robots.txt`, `sitemap.xml`, внутренние ссылки, alt у изображений и грубые размеры ассетов.
- Проверка schema проводилась по rendered static HTML в `dist/`, не через `curl`.

## Findings

### P0. Юридические ссылки ведут на 404

Во всех страницах есть ссылки `/privacy`, `/consent`, `/terms`, но таких страниц в сборке нет. Источники:

- `src/components/site/sections/Footer.astro`: legal links.
- `src/components/site/sections/FinalCTA.astro`: ссылка согласия на `/privacy`.
- `src/components/site/BookingModal.astro`: ссылка согласия на `/privacy`.

Риск: 404 из футера и форм, просадка доверия, юридический риск по 152-ФЗ, ухудшение качества посадочной страницы для Яндекс Директа.

Рекомендация: добавить реальные страницы или изменить ссылки на существующий `/documents/` с якорями. Для рекламы лучше иметь отдельные URL: `/privacy/`, `/consent/`, `/terms/`.

### P1. Не подключена Яндекс.Метрика

В коде не найдено `astro-ym`, `ym(`, `YANDEX_COUNTER_ID` или счетчик Метрики. В `package.json` зависимости `astro-ym` тоже нет.

Риск: без Метрики нельзя нормально оптимизировать Директ, цели форм/мессенджеров/кликов не будут измеряться.

Рекомендация: подключить Метрику в layout сразу в `<head>`, завести цели: отправка формы, открытие модалки, `tel:`, WhatsApp, Telegram, Max, переход к ценам, клик по услуге.

### P1. Общий JSON-LD слишком слабый и одинаковый на всех страницах

Сейчас `SiteLayout.astro` ставит один `MedicalClinic` JSON-LD на каждую страницу, а `url` меняется на URL текущей страницы. В schema нет `logo`, `image`, `geo`, `sameAs`, `hasMap`, `areaServed`, `email`, `addressRegion`, `postalCode`, `founder`/`legalName` при необходимости.

Риск: размытый сигнал. Для внутренних страниц клиника выглядит как отдельная сущность на каждом URL, а не как организация плюс конкретная страница услуги.

Рекомендация: на layout оставить `MedicalClinic` с `@id` главной организации (`https://kzn.platinental.ru/#clinic`) и `url` главной. Для страниц направлений добавить `MedicalWebPage`/`Service` + `BreadcrumbList`. Для `/contacts/` усилить `MedicalClinic` контактными и geo-полями.

### P1. Часть title слишком короткие и не забирают спрос

Текущие title:

- `/kosmetologiya/`: `Косметология — The Platinental Казань`, 37 символов.
- `/kosmecevtika/`: `Космецевтика — The Platinental Казань`, 37 символов.
- `/prices/`: `Прайс-лист — The Platinental Казань`, 35 символов.
- `/contacts/`: `Контакты — The Platinental Казань`, 33 символа.
- `/about/`: `О клинике — The Platinental Казань`, 34 символа.

Риск: низкая релевантность коммерческим запросам в Яндексе и Google. Страницы направлений должны явно содержать `в Казани`, ключевые процедуры и намерение пользователя.

Рекомендация:

- `/kosmetologiya/`: `Косметология в Казани: инъекции, аппаратные процедуры | The Platinental`.
- `/kosmecevtika/`: `Профессиональная космецевтика в Казани | The Platinental`.
- `/prices/`: `Цены на пластическую хирургию и косметологию в Казани | The Platinental`.
- `/contacts/`: `Контакты клиники The Platinental в Казани: адрес, телефон, карта`.
- `/about/`: `О клинике The Platinental Казань: пластическая хирургия и косметология`.

### P1. Meta descriptions местами длиннее SERP-диапазона

Длинные descriptions:

- `/plastika/`: 182 символа.
- `/about/`: 161 символ.

Риск: сниппет будет обрезан, CTA и важные ключи могут исчезнуть.

Рекомендация: держать 120-155 символов, первый фрагмент делать самодостаточным. Пример для `/plastika/`: `Пластическая хирургия в Казани: ринопластика, блефаропластика, SMAS-лифтинг, маммопластика. Консультации в The Platinental.`

### P1. Большие ассеты в audit scope

Даже без страниц врачей есть тяжелые ресурсы:

- `/` ссылается примерно на 3.0 MB локальных ассетов без учета doctor assets.
- `/before-after/mardanova-rhinoseptoplasty.jpg`: 1.5 MB, используется на главной.
- `/quote/iskornev-portrait-2026.png`: 878 KB, используется как default OG image и на ряде страниц.
- Папка `dist/before-after`: 19 MB.

Риск: хуже LCP и мобильный опыт, особенно для рекламного трафика. Яндекс тоже учитывает качество посадочной и поведенческие.

Рекомендация: конвертировать крупные JPG/PNG в WebP/AVIF, задать responsive sizes, проверить, какие before-after реально нужны на главной, и не тянуть тяжелые изображения вне видимой области.

### P2. Sitemap минимальный

`sitemap.xml` содержит URL, но без `lastmod`, `changefreq`, `priority`. Это не ошибка, но для статического сайта с ручной публикацией лучше добавить `lastmod`.

Риск: слабее сигнал об обновлениях, сложнее диагностировать индексирование после релизов.

Рекомендация: добавить `lastmod` для статических маршрутов и генерировать дату из build/config или из данных страницы.

### P2. Sitemap включает врачей

`sitemap.xml.ts` добавляет `...doctors.map(...)`. В текущем аудите врачи исключены, поэтому качество этих URL не оценивалось.

Риск: если врачебные страницы ещё не готовы юридически/контентно, они уже попадут в sitemap и могут индексироваться.

Рекомендация: перед запуском рекламы решить, индексируем ли `/doctors/` и `/doctors/*` сейчас. Если нет, временно убрать их из sitemap или поставить `noindex` до готовности.

### P2. Нет page-specific structured data для FAQ и breadcrumbs

На страницах есть FAQ-блоки и логичная структура разделов, но в HTML найден только один `MedicalClinic` JSON-LD.

Риск: недоиспользуется шанс на расширенный сниппет и понятную структуру сайта для поисковика.

Рекомендация: добавить `BreadcrumbList` на внутренние страницы. `FAQPage` использовать аккуратно: только если вопросы и ответы видимы пользователю и не являются рекламным/медицински рискованным обещанием.

### P2. Документы перечислены, но не скачиваются

На `/documents/` элементы отображают `Скачать`, но `href: null`, кнопки disabled. Это уже зафиксировано в соседнем текстовом аудите.

Риск: для медицинской клиники это trust-сигнал. Пользователь и модерация рекламы могут ожидать доступные лицензии и политики.

Рекомендация: подключить финальные PDF или заменить механику на честный текст до готовности файлов. При подключении документов обновить футерные ссылки из P0.

## Что в порядке

- У всех страниц scope ровно один H1.
- У всех страниц scope есть уникальные `title`, `description`, canonical, OG и Twitter meta.
- Canonical URL согласованы с sitemap и ведут на `https://kzn.platinental.ru/.../`.
- `robots.txt` разрешает обход и указывает sitemap.
- У изображений на проверенных страницах есть `alt`.
- 404-страница имеет `noindex, follow`.
- Текстового объема достаточно для ключевых посадочных: главная около 1568 слов, пластика около 1606, косметология около 1167, цены около 2331.

## Приоритетный план исправлений

1. Создать `/privacy/`, `/consent/`, `/terms/` или временно заменить все юридические ссылки на `/documents/`.
2. Подключить Яндекс.Метрику и цели под Директ.
3. Переписать title/description для `/kosmetologiya/`, `/kosmecevtika/`, `/prices/`, `/contacts/`, `/about/`, `/plastika/`.
4. Разделить JSON-LD: организация с постоянным `@id`, breadcrumbs, service/page schema на направления.
5. Сжать тяжелые изображения главной и before-after.
6. Решить статус врачебных URL в sitemap до индексации.
7. Подключить реальные PDF/страницы документов.
