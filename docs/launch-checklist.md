# Чек-лист сдачи сайта The Platinental Казань

Дата: 2026-05-14  
Статус: рабочий чек-лист перед финальной проверкой и запуском.

## 0. Доступы и исходная инфраструктура клиента

- [ ] Получить доступ к текущему домену `kzn.platinental.ru`: регистратор, DNS-зона, кто владелец, где меняются A/CNAME/TXT.
- [ ] Получить доступ к текущему хостингу сайта: панель, FTP/SSH или админка, где лежит активный сайт, есть ли резервные копии.
- [ ] Получить доступ к текущей Яндекс.Метрике: номер счетчика, владелец, права `Can edit` или представительский доступ.
- [ ] Получить доступ к Яндекс.Вебмастеру для `kzn.platinental.ru`: роль Owner или подтверждение прав через DNS/HTML/meta.
- [ ] Уточнить, есть ли Google Search Console и нужен ли Google как вторичный канал.
- [ ] Получить доступы или контакты ответственных по Яндекс.Директ: Александр + Андрей / New Age, список целей, UTM-метки, посадочные.
- [ ] Уточнить, нужно ли переносить старые URL, страницы, документы, изображения, отзывы, формы и цели из текущего сайта.
- [ ] Сделать бэкап текущего сайта до переключения DNS.

## 1. Индексация и краулинг

- [ ] `robots.txt` доступен по `/robots.txt`, не закрывает важные страницы.
- [ ] В `robots.txt` указан абсолютный URL sitemap.
- [ ] `sitemap.xml` доступен, валиден, содержит только канонические индексируемые URL.
- [ ] В sitemap есть нужные публичные страницы: главная, направления, услуги, врачи, цены, контакты, документы.
- [ ] Страницы, которые не готовы юридически или контентно, временно исключены из sitemap или закрыты `noindex`.
- [ ] Все важные страницы отдают `200`, нет случайных `3xx`, `4xx`, `5xx`.
- [ ] Кастомная 404-страница отдает реальный HTTP 404, содержит навигацию и CTA.
- [ ] Нет битых внутренних ссылок.
- [ ] Нет orphan-pages: каждая важная страница достижима из навигации, футера, карточек или хлебных крошек.
- [ ] URL единообразны: `https`, один домен, trailing slash по принятому правилу.
- [ ] HTTP и альтернативные варианты домена редиректят на канонический HTTPS URL.

## 2. On-page SEO

- [ ] На каждой странице уникальный `<title>`, с гео `Казань`, без дублей.
- [ ] На каждой странице уникальный `<meta name="description">`, без обрезанных или шаблонных описаний.
- [ ] На каждой странице ровно один `<h1>`.
- [ ] H1, первый экран и лид отражают реальный интент страницы: пластика, косметология, космецевтика, врач, цена, контакт.
- [ ] Для страниц услуг есть гео-привязка: title, H1 или первый абзац, description.
- [ ] Заголовочная структура логична: H2/H3 без перескоков ради визуального размера.
- [ ] Все изображения имеют осмысленный `alt`, декоративные не мешают скринридерам.
- [ ] Контент не содержит запрещенных формулировок проекта: филиал, международный бренд, американский бренд, методика Искорнева для всей клиники.
- [ ] Не используются запрещенные AI-паттерны: `не просто..., а...`, `это не X, а Y`, `не заменяет консультацию`.
- [ ] Нет универсальной заглушки `по показаниям` без конкретного критерия.
- [ ] Все факты о врачах, лицензиях, ценах, операционных базах и аппаратах сверены с `knowledge/`.

## 3. Schema.org и сниппеты

- [ ] На главной есть корректный `MedicalClinic` с постоянным `@id`, адресом, телефоном, гео, URL, logo/image.
- [ ] На страницах врачей есть `Physician`, без неподтвержденных квалификаций.
- [ ] На страницах услуг есть релевантная schema: `MedicalProcedure` или `Service`.
- [ ] На страницах космецевтики есть schema только для реальных карточек, без выдуманных цен и наличия.
- [ ] На внутренних страницах есть `BreadcrumbList`.
- [ ] FAQ schema добавлена только там, где FAQ видим пользователю и ответы безопасны по медицине/рекламе.
- [ ] JSON-LD проверен в rendered HTML или браузере, не только через `curl`.
- [ ] Rich Results / валидаторы не показывают критичных ошибок.

## 4. Техническая производительность

- [ ] `npm run check` проходит.
- [ ] `npm run build` проходит.
- [ ] Lighthouse/PageSpeed проверены минимум для главной, пластики, косметологии, врача, цены, контактов.
- [ ] Core Web Vitals: LCP < 2.5s, INP < 200ms, CLS < 0.1 как целевой ориентир.
- [ ] Hero и first viewport не тянут лишние тяжелые изображения.
- [ ] Крупные фото оптимизированы WebP/AVIF или сжаты без заметной потери качества.
- [ ] Изображения имеют width/height или стабильный aspect-ratio.
- [ ] Шрифты подключаются стабильно, без сильного layout shift.
- [ ] Нет лишнего JavaScript на статических страницах.
- [ ] Нет ошибок в browser console на ключевых страницах.
- [ ] Сайт корректно работает при медленном мобильном интернете.

## 5. Мобильная и визуальная проверка

- [ ] Проверены viewport: 1440x900, 1024x768, 375x812.
- [ ] Нет горизонтального скролла.
- [ ] Текст не налезает на кнопки, карточки, фото и соседние блоки.
- [ ] CTA видны и нажимаемы на мобильном.
- [ ] Tap targets достаточно крупные.
- [ ] Header, бургер, футер, формы, модалки, карточки врачей и цены работают на мобильном.
- [ ] Цвета соответствуют проекту: cream, black, champagne; нет красного и темных доминантных фонов.
- [ ] Фото и before/after не ломают премиальный тон и не выглядят как stock.

## 6. Формы, заявки и конверсии

- [ ] Все формы отправляют заявку в согласованный канал: WhatsApp, Telegram, почта, CRM или ручной процесс.
- [ ] Если 1С УМЦ не интегрируется, это не подразумевается в интерфейсе.
- [ ] Поля формы минимальны и понятны.
- [ ] На каждой форме есть отдельный не предзаполненный чекбокс согласия на обработку ПД.
- [ ] Без чекбокса форма не отправляется.
- [ ] После отправки пользователь видит понятное состояние успеха или ошибку.
- [ ] `tel:`, WhatsApp, Telegram и Max ведут в реальные контакты клиники.
- [ ] Max-ссылка заменена с временной на реальную или скрыта до подтверждения.
- [ ] Все CTA передают события в Метрику.

## 7. Яндекс.Метрика, Вебмастер и Директ

- [ ] Счетчик Метрики установлен на все страницы.
- [ ] Включены Вебвизор, карта кликов, карта скроллинга, если клиент и юрист согласовали cookie/аналитику.
- [ ] Цели заведены: отправка формы, открытие формы/модалки, клик телефона, WhatsApp, Telegram, Max, переход к ценам, клик по врачу, клик по услуге.
- [ ] JavaScript-события вызывают `reachGoal` с теми же ID, что заведены в счетчике.
- [ ] New Age получили доступ к целям для оптимизации Директа.
- [ ] UTM-метки Директа сохраняются и не ломаются редиректами.
- [ ] В Метрике видны тестовые визиты и тестовые достижения целей.
- [ ] Сайт добавлен в Яндекс.Вебмастер.
- [ ] В Вебмастере отправлен sitemap.
- [ ] Проверены диагностика сайта, robots.txt, sitemap, SSL, серверный ответ, страницы в индексе.
- [ ] После запуска отправлены ключевые страницы на переобход.

## 8. Юридические и медицинские требования

- [ ] На сайте доступны политика обработки персональных данных, согласие на обработку ПД, пользовательские условия или документ с условиями заявки.
- [ ] В футере есть юридическое лицо: ООО `Платинентал Казань`.
- [ ] Есть номер лицензии и ссылка/файл лицензии, если клиент передал финальный документ.
- [ ] На страницах с медицинскими услугами есть корректный дисклеймер про противопоказания и консультацию специалиста.
- [ ] Цены сопровождаются пометкой, что информация не является публичной офертой.
- [ ] Все документы открываются и скачиваются, если кнопка называется `Скачать`.
- [ ] Хостинг и обработка данных соответствуют 152-ФЗ: российская инфраструктура или подтвержденная схема клиента.
- [ ] Cookie/аналитика описаны в политике, баннер добавлен при необходимости.
- [ ] Никакие медицинские обещания не звучат как гарантия результата.

## 9. Контент и фактическая проверка

- [ ] Врачи названы полным ФИО или форматом `Фамилия И.О.` в публичных текстах.
- [ ] Никаких неподтвержденных цен, стажа, дипломов, аппаратов, адресов, фото до/после.
- [ ] Страницы врачей сверены с `src/data/doctors.ts` и `knowledge/doctors.md`.
- [ ] Операционные базы Корл и `Миллениум` упоминаются нейтрально, без промо сторонних клиник.
- [ ] INDIBA не показывается как доступная услуга до подтверждения.
- [ ] Отзывы с Яндекс.Карт/2ГИС/ПроДокторов используются с источником и аккуратной редактурой.
- [ ] Фото врачей и кейсы согласованы клиентом.
- [ ] На страницах нет внутренних пометок: `по клиентской вводной`, `согласовать`, `TODO`, `рабочая версия`.

## 10. Миграция, домен и запуск

- [ ] Зафиксирован список старых URL текущего сайта.
- [ ] Для старых URL составлена карта 301-редиректов на новые страницы.
- [ ] Проверены канонические URL после переключения домена.
- [ ] DNS TTL снижен перед запуском, если это нужно для быстрого переключения.
- [ ] SSL выпущен и работает после переключения.
- [ ] Сайт доступен из РФ.
- [ ] Проверены `www`/без `www`, HTTP/HTTPS, slash/non-slash.
- [ ] Старый сайт сохранен в бэкапе.
- [ ] После переключения проверены формы, Метрика, Вебмастер, sitemap, robots, 404, редиректы.
